# HALOGY CHANGE LOG
--------------------

## Version 2.0.0 (community fork)

- **Runs on modern PHP and databases**: PHP 8.1 or later (tested on 8.3), MariaDB 10.x / MySQL 8; CodeIgniter 2.1 core and HMVC patched for PHP 8; known PHP 8 fatal errors and deprecation warnings fixed across all modules (pages, blog, events, shop, forums, wiki, community, webforms, files, images, users, admin); mysqli driver replaces removed mysql extension; permissive session sql_mode set on connect (dump uses zero dates); DB settings from HALOGY_DB_HOST/USER/PASS/NAME env vars; environment from HALOGY_ENV (defaults to production); ZipArchive replaces removed zip_* functions for image and template zip uploads.

- **Security**: passwords stored with password_hash(); existing MD5 passwords upgraded automatically on next login; remember-me cookie replaced with a signed token (the old one stored the plaintext password and was unserialized from the request); session cookies signed with HMAC-SHA256, random session IDs, regenerated on login, HttpOnly/SameSite; encryption key read from HALOGY_ENCRYPTION_KEY or generated per install (no more shared hard-coded key); fixed privilege escalation where public registration and account forms accepted a posted groupID (an anonymous visitor could make themselves an administrator); CSRF tokens required on POST requests (same-origin forms and AJAX requests get the token automatically) and on GET links to state-changing actions whose method names match a configurable list (delete/approve/publish/revert/logout and similar); payment gateway callbacks are exempt; production mode hides PHP and database errors; uploads directory blocks script execution; dangerous file types removed from upload allow-lists; security headers (nosniff, X-Frame-Options, Referrer-Policy); random reset keys and generated passwords; unserialize hardened; SQL injection hardening of admin list ordering; backup no longer leaks other sites' tags.

- **Fixes**: missing "pages_navigation" permission added (navigation admin was inaccessible); backup works with tables lacking siteID; shop upsell rule, order sorting, cart quantity validation; forums/wiki/community fatals; events tag pages; template editor JS error with jQuery 2; webform account creation fatal.

- **Docker**: Dockerfile (PHP 8.3 + Apache) and docker-compose.yml (MariaDB 10.11) for one-command local setup. The image generates its own encryption key at build time (override with HALOGY_ENCRYPTION_KEY; rebuilding without it logs everyone out). docker-compose.yml sets HALOGY_ENV=development, which shows PHP and database errors, so do not expose it publicly.

- **Upgrading an existing install**: back up first; run halogy/sql/upgrade-2.0.sql BEFORE deploying the new code or logging in (widens ha_users.password to 255 characters so password hashes are not truncated, and adds the pages_navigation permission; assumes the default ha_ table prefix); check the requirements: PHP 8.1 or later with mysqli, gd, zip and mbstring, and a non-strict MySQL/MariaDB sql_mode (see Requirements); if you run more than one web server, set the same HALOGY_ENCRYPTION_KEY on all of them; changing or losing the key logs everyone out; script execution in static/uploads is blocked by an Apache .htaccess; on other web servers (e.g. nginx) configure the equivalent yourself; upload allow-lists were tightened (no js/swf; dangerous types are stripped from web form file types), so review your web form file type settings; all users are logged out once, including remember-me logins (cookie formats changed); they can log in with their existing passwords; the SQL only adds the permission; tick 'Allow Navigation' for each admin group that needs it; configure the database using the new halogy/config/database.php which reads HALOGY_DB_HOST/USER/PASS/NAME (defaults: localhost, halogy, halogy, halogy) and uses the mysqli driver, or edit that file and re-enter your credentials and table prefix (dbprefix is ha_); if you keep your old database.php instead, change dbdriver to mysqli (the old mysql extension was removed in PHP 7); HALOGY_ENV defaults to production, which hides errors; if the upgraded site shows a blank page or HTTP 500, set HALOGY_ENV=development temporarily to see the error; if you let the app create halogy/config/encryption_key.php, make halogy/config read-only again afterwards.

- **Known limitations**: still CodeIgniter 2.1 underneath (end-of-life framework, patched, not upgraded); some state-changing GET routes are not CSRF-protected (for example, GET admin/pages/add creates a draft page); upload script blocking relies on an Apache .htaccess file; changing your password from the front-end account page does not ask for the current password (account forms are per-site templates); forgotten-password pages reveal whether an email is registered, and reset emails include a new plaintext password; reset keys don't expire; backups include only tables with a siteID column (plus tags) — custom tables without siteID are exported as schema only; a CSRF token rotated by logging in in one tab makes other open tabs show an error until reloaded. This fork as a whole is not recommended for production or internet-facing use.
